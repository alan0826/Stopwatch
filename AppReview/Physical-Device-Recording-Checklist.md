# Build 3 送審前檢查清單

> 前兩次 5.6 退件最可能的原因：Build 1 審查期間，送審資料已經在描述 Build 1 沒有的 AlarmKit 功能。
> 這次的原則只有一條：**審查員看得到的每一句話、每一張圖、每一段影片，都必須能在 Build 3 裡原樣找到。**

## 1. App Store Connect 設定

- 「定價與供應狀況」裡，取消勾選 **iPhone 與 iPad App 可在 Apple 晶片 Mac 上使用** 和 **Apple Vision Pro**。
  退件信附了「在相容裝置上支援 App」的連結；AlarmKit 與動態島在 Mac／Vision Pro 上的表現無法保證，別讓審查員在那裡測。
- 送審項目裡掛的 build 必須是 `1.0 (3)`。

## 2. 送審資料（全部對照 Build 3 重新檢查）

- 截圖：刪掉所有舊截圖，只用 Build 3 實機畫面重拍。不要放 Build 3 沒有的畫面，也不要放概念圖或合成圖。
- 描述：使用 `App-Description-zh-Hant.txt`。若有英文或其他語系的描述，也要逐句同步。
- 推廣文字：使用 `Promotional-Text-zh-Hant.txt`。
- 審查備註：使用 `Review-Notes-en.txt`，裡面引用的中文按鈕名稱都是畫面上實際的字。
- 回覆審查：使用 `Reply-to-Review-en.txt`，把 `[iPhone model]`、`iOS [full version]`、`[date]` 換成實際錄影資訊。回覆裡寫「已更新」的項目，送出前都要真的更新完。

## 3. 錄影前

- 刪除舊版 App，從 TestFlight 安裝 `1.0 (3)`，確保是全新首次啟動。
- 使用 iOS 26 以上的實體 iPhone，記下機型與完整 iOS 版本。
- 全程不中斷、不剪接、不加速。

## 4. 影片 A：一般通知

1. 從主畫面開啟 App，證明不會自動跳出任何權限視窗。
2. 點左上角 ⓘ，完整展示「關於循環提醒」頁（功能、系統需求、版本 `1.0 (3)`）。
3. 點 ＋，保持「重複」，選「每 1 分」，第一次響鈴設 1～2 分鐘後，按「儲存」。
4. 展示主畫面出現提醒與橘色的「開啟背景提醒」卡片，儲存時沒有跳權限視窗。
5. 點「開啟背景提醒」，在系統視窗允許通知。
6. 鎖定 iPhone，等提醒實際出現在鎖定畫面並發出聲音。
7. 解鎖回到 App，展示「提醒紀錄」、開關、編輯與左滑刪除。

## 5. 影片 B：系統鬧鐘（iOS 26）

1. 點 ＋，選「單次」，打開「持續響鈴直到停止」，時刻設 1～2 分鐘後，按「儲存」。
2. 在主畫面點橘色的「開啟系統鬧鐘」卡片，允許鬧鐘權限。
3. 鎖定 iPhone，等系統鬧鐘畫面與聲音出現。
4. 若機型有動態島，也拍到動態島上的鬧鐘。
5. 按「停止」，證明鬧鐘停下。（App 沒有「稍後提醒」，不要在影片或備註裡提到。）

## 6. 若另有 iOS 18～25 的實機（選擇性）

1. 點 ＋ 選「單次」，展示「持續響鈴直到停止」仍然看得到，但開關是停用的，下方寫著需要 iOS 26。
2. 展示一般通知提醒照常建立與送達。
